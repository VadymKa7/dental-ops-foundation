# Dental Operations Intelligence

Learning and portfolio backend for a dental operations product. This repository is the foundation: a single FastAPI process, PostgreSQL, one users example, tests, and a local Docker Compose stack.

**Staff authentication is a server-side session.** Patients are stored without a password and cannot sign in. The first administrator is created with `POST /api/v1/auth/bootstrap` while no staff account exists. Do not deploy this service with real patient or customer data until the production items in `docs/ROADMAP.md` exist.

Appointments, document extraction, AI providers, and video processing are described in module READMEs and the roadmap. They are not implemented. Redis runs in Compose for a future worker. The API process does not connect to it. Celery is not installed.

## Prerequisites

- Python 3.12 or newer
- [uv](https://docs.astral.sh/uv/)
- Docker with Compose v2, when you want PostgreSQL, Redis, or the API container

Commands below are run from the repository root.

## Setup

```bash
uv sync
cp .env.example .env
```

`.env.example` contains local placeholders only. `uv sync` creates `.venv` and installs the locked dependencies, including the development tools.

Start PostgreSQL and Redis:

```bash
docker compose up -d postgres redis
```

Compose creates two databases on a fresh volume:

- `dental` for the application
- `dental_test` for pytest

The Postgres password in Compose (`dental`) is a local placeholder. The API container does not start in the command above.

## Migrations

Alembic is the schema tool. The application does **not** run migrations on startup and does not call `create_all()`.

```bash
uv run alembic upgrade head
```

That applies every revision in `migrations/versions/` using `DATABASE_URL` from the environment or `.env`.

Other commands:

```bash
uv run alembic downgrade base
uv run alembic revision --autogenerate -m "describe the change"
```

Review an autogenerated revision before you apply it. Run Alembic from the repository root.

From the API image, after `docker compose build api`:

```bash
docker compose run --rm api alembic upgrade head
```

## Run the API

On the host, against the Compose Postgres published on port 5432:

```bash
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --no-access-log
```

`--no-access-log` avoids a second access log. The application writes one JSON line per request with method, path, status, and duration. Query strings and bodies are not logged.

Or build and run the whole stack. The API image still does not migrate itself:

```bash
docker compose up -d --build
docker compose run --rm api alembic upgrade head
```

Health routes are unversioned, at the process root, so probes do not depend on the API version:

- `GET /health/live` — the process is up. It does not touch the database.
- `GET /health/ready` — the database accepts `SELECT 1`. This does not prove migrations are current. Until Postgres is reachable, ready returns 503.

Business routes live under `/api/v1`:

- `POST /api/v1/auth/bootstrap`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/logout`
- `POST /api/v1/users`
- `GET /api/v1/users`
- `GET /api/v1/users/{user_id}`
- `GET /api/v1/audit`

Interactive docs: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

```bash
curl http://127.0.0.1:8000/health/live
curl http://127.0.0.1:8000/health/ready
curl -X POST http://127.0.0.1:8000/api/v1/auth/bootstrap \
  -H 'content-type: application/json' \
  -d '{"display_name":"Ada Admin","email":"ada.admin@example.com","password":"password123"}'
```

Emails are stored lowercase. A duplicate email, including a different case, returns 409. An unknown user returns 404. Invalid JSON bodies return 422. Error JSON looks like:

```json
{"error": {"code": "user_not_found", "message": "User not found.", "details": null}}
```

Health routes stay public. User and audit routes require `Authorization: Bearer <token>`. Swagger's Authorize box wants the raw token.

## Tests

Unit tests do not need PostgreSQL:

```bash
uv run pytest -m "not integration"
```

Integration tests use PostgreSQL through asyncpg. They do not fall back to SQLite. Point `TEST_DATABASE_URL` at an empty database, never at production or personal data. Pytest reads that variable from the process environment. It does not read it from `.env`.

```bash
export TEST_DATABASE_URL=postgresql+asyncpg://dental:dental@localhost:5432/dental_test
uv run pytest
```

The integration fixture runs `alembic upgrade head` against that database and truncates `users` and the tables that reference it after each test. Set `REQUIRE_INTEGRATION=1` when a missing URL should fail the run instead of skipping, which is what a future CI job should do.

```bash
REQUIRE_INTEGRATION=1 TEST_DATABASE_URL=postgresql+asyncpg://dental:dental@localhost:5432/dental_test uv run pytest
```

If the Compose volume was created before `docker/postgres/init` existed, create the test database once:

```bash
docker compose exec postgres psql -U dental -d dental -c "CREATE DATABASE dental_test;"
```

```bash
uv run ruff format

uv run ruff check

```

`mypy` is configured in strict mode for `app` and `tests`. Migration scripts are executed by Alembic and are outside that check.

## Layout

`docs/ARCHITECTURE.md` describes module boundaries, the request and session lifecycle, and how to add a module. `docs/LEARNING_GUIDE.md` walks the same code for someone learning Python backends. `docs/ROADMAP.md` lists later stages. ## Local configuration

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | SQLAlchemy URL. It must start with `postgresql+asyncpg://`. |
| `TEST_DATABASE_URL` | Empty database used only by integration tests. |
| `REDIS_URL` | Reserved for a future worker. Unread by the API. |
| `ENVIRONMENT` | `local`, `test`, or `production`. `production` rejects `DEBUG=true`. |
| `LOG_LEVEL` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, or `CRITICAL`. |
| `API_PREFIX` | Prefix for business routes. Default `/api/v1`. |
| `DATABASE_CONNECT_TIMEOUT_SECONDS` | Connection timeout passed to asyncpg. |
| `SESSION_TTL_MINUTES` | Lifetime of a staff session. Default 480. The raw token is not stored. |

Logs are JSON. The formatter writes a fixed set of fields and drops exception text, so a database error does not copy a URL or a row into the log line.
